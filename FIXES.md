# Исправления и запуск

Ветка исправляет изоляцию аккаунтов, сохранение данных, каталог админки, плеер, RU/EN-привязку аудио, сброс пароля, обработку null в админке, календарные дни, PWA-пути и доступ к ИИ. Оплата и тарифы не изменены: они запланированы на следующий этап.

## Проверенный статус выпуска

Обе согласованные миграции базы применены и проверены. Основная версия ещё не обновлена. Действующий сайт использует встроенный каталог и 15 MP3 в `/audio`, а каталог и Storage в Supabase пусты.

Сборка сохраняет существующие аудиофайлы: `scripts/preserve-audio.mjs` получает отсутствующие файлы с действующего сайта и сверяет размеры и SHA-256 с `scripts/audio-manifest.json`. Если файл недоступен или изменён, сборка останавливается. Записи не включаются в публичный GitHub. Храните независимую резервную копию: сборка зависит от доступности текущего сайта, пока нет отдельного хранилища.

Встроенный каталог сохранён по умолчанию. `VITE_CATALOG_SOURCE=remote` можно включать только после заполнения и проверки каталога Supabase.

## Перед обновлением рабочей версии

1. В Supabase SQL Editor выполнить `supabase_ai_quota.sql`. Этот файл создаёт лимит 20 запросов в минуту и 100 в день на пользователя. До выполнения миграции ИИ-функции намеренно возвращают 503, чтобы не разрешать запросы без действующего ограничения. Данные дневников не затрагиваются.
2. Проверить серверные `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `ANTHROPIC_API_KEY` и клиентские переменные по `.env.example`. Допускаются прежние `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` на сервере. Секрет Anthropic должен быть только на сервере.
3. Для iOS указать `VITE_API_BASE_URL` — реальный HTTPS-домен размещённых API; `VITE_AUTH_REDIRECT_URL` — разрешённую в Supabase ссылку на веб-форму восстановления. Для дополнительных веб-доменов задать `AI_ALLOWED_ORIGINS` через запятую. Native origins поддержаны отдельно.
4. Проверить каталог Supabase: он становится основным источником только при `VITE_CATALOG_SOURCE=remote`. Успешный пустой ответ означает пустую библиотеку; неактивные записи не возвращаются из статического fallback. При недоступности сервера используется последний кэш, а при отсутствии кэша — встроенный каталог.
5. Подключить записи через `audio_url` в админке. Альтернатива для исходных 15 записей: `VITE_AUDIO_BASE_URL` с каталогом тех же имён файлов либо реальные файлы в `public/audio/` перед build. Отсутствующие файлы больше не обозначаются доступными. Русская озвучка не переводится автоматически: EN меняет название, для встроенной записи показывается язык Russian.
6. Если используется `supabase_rls_admin.sql`, исправленная версия выполняется транзакционно и предназначена для уже существующих таблиц meditations/sections. Неадминистраторы читают только активные строки. Перед применением проверить текущие политики: этот файл меняет только перечисленные в нём политики, другие политики не удаляет. Реальные политики проверены: дополнительные разрешающие чтение политики также ограничены. Storage пуст.
7. После сборки проверить два тестовых аккаунта на одном устройстве и один аккаунт на двух устройствах. Проверить воспроизведение на физическом iPhone, блокировку экрана, письмо восстановления и ИИ. Локальные тесты не заменяют эту проверку.

## Существующие локальные данные

Старая версия хранила дневники в общих ключах без владельца. Эти старые ключи **не удаляются**, но не присваиваются автоматически вошедшему пользователю: после обнаруженного смешивания аккаунтов это было бы небезопасно. Синхронизированные данные загружаются из личной строки Supabase. Если у тестировщицы есть только локальные записи старой версии, до обновления нужно сохранить их копию и отдельно подтвердить принадлежность для переноса. Общие старые данные могут уже содержать записи разных людей; автоматическое восстановление владельца невозможно.

Новая локальная копия хранится под отдельным ключом userId, сохраняет изменения при ошибке сети и повторяет синхронизацию. Серверные записи обновляются только при совпадении известной версии. Если другое устройство успело сохранить изменения, обе копии сохраняются, интерфейс сообщает о конфликте. Автоматического слияния дневников/удалений и интерфейса разрешения конфликтов в этой ветке нет; конфликт нужно разобрать отдельно, не очищая локальную копию.

## Проверки

`npm ci --ignore-scripts` → `npm test` → `npm run build`.

Тесты используют искусственные аккаунты и подменённые серверы. Они не выполняют реальные покупки, платные ИИ-запросы и не меняют рабочую базу. Плеер проверяется React-тестом с заменённым аудиоэлементом, а не реальным декодированием MP3. Согласованные миграции ИИ и ограничения прав применены на рабочем Supabase; права проверены SQL-запросами.

`npm run lint` всё ещё выявляет прежние стилистические ошибки и нарушения React-правил в проекте. Массовая переработка этих экранов не включена в исправления. Размер основного JS-пакета остаётся большим; оптимизацию загрузки следует делать отдельно после функциональной проверки.

## Веб-установка

По умолчанию приложение собирается для `/`. Для статической подпапки можно указать `APP_BASE_PATH=/frisson-app/`. Манифест и service worker используют тот же путь. Service worker кэширует только оболочку (HTML/JS/CSS), не дневники, API или аудиозаписи. Офлайн-запуск требует хотя бы одного успешного онлайн-открытия и ранее загруженной сессии/локальных данных. GitHub Pages не исполняет серверные API — им нужен отдельный HTTPS-backend.
